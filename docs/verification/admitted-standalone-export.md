# Private admitted standalone export

Status: locally verified private agent/engine slice; public export jobs remain pending.
Owner: [admitted export contract](../design/lld/admitted-standalone-export.md).
This evidence does not complete F15 or qualify a public release.

## Implemented boundary

Dedicated authenticated export intake captures the full immutable assignment.
Journal015 retains purpose and exact digest through replay, refusal, cancellation
and recovery. Admission reserves both original Offer and assignment staging bytes.
The installed offline export profile binds a fixed entrypoint and assignment digest
into the trusted Docker specification and staged header. Ordinary intake cannot
select this purpose. No performance Run or verdict is synthesized.

The shared compiler/build operation publishes one separately sealed export result.
Native collection, source sealing and chunk transfer retain the existing physical
custody checks. The result codec follows durable purpose; it never retries another
codec after a failed seal. Known stop and verified custody precede capacity release.

## Native Docker proof

On Linux arm64 under Docker Desktop29.9.2, task-owned Node24 images exercised the
actual private agent HTTP routes, Journal, Docker controller and export entrypoint.

- An accepted reply was discarded; exact replay created one engine only.
- Engine exited0, without OOM, with network mode `none`.
- The downloaded23,313-byte script matched its sealed SHA256 and actual source.
- Wrong-scope source access returned404; altered assignment returned409.
- Agent restart preserved Journal authority and the exact verified source envelope.
- Fresh cancellation followed by late replay returned the durable rejected/cancelled
  snapshot and created no second engine. Replay202 is receipt acknowledgement.
- Synthetic target observed zero readiness, work or unexpected requests.
- All task-owned containers/networks were removed after the proof.

Images were built from uncommitted source with per-image file/hash vectors,
not represented as exact-commit CI or published release artifacts. The capped
BuildKit owner used2CPU/2GiB/512PIDs and a1GiB cache GC target; that target is not a
hard peak disk quota. The final agent/image IDs and full local logs are retained in
the coordinator's private evidence. One optional agent log capture failed; native
inspection, HTTP assertions, source bytes and cleanup evidence were retained.

A separate ordinary k6 Docker job passed through the same changed lifecycle:
one readiness and one work request, exited0, six artifacts/25,688bytes verified
through source chunks, released reservation and successful task cleanup.

## Limits

automation client are not implemented by this slice. Native amd64, packaged browser,
release installation, abuse/soak and full crash-during-generation qualification

chain; it did not claim those remaining capabilities.

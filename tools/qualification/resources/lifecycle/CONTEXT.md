# Packaged active lifecycle qualification

Manual run.ts PUBLICATION_JSON NEW_ABSOLUTE_OUTPUT [LOCAL_CONTEXT] [crashes|cancel]. Requires six
already available immutable published images; no build/pull or user installation.
Same native Compose/default runtime UID/caps/reserve. Optional target request cap
is128 here; ordinary Compose smoke keeps4. OneVU/40iterations/500ms per run,
30smaxDuration, two crash runs or one cancel run per fresh project, 600s outer check-runner. Observe eight real
requests before backend SIGKILL, agent SIGKILL or public cancel. Only exact owned
service ID/project/role/image may receive a fault. Explicitly restart that same
stopped service; Docker CLI kill can suppress automatic policy. Record the route. Independent review before runs.

Require same original attempt/generation/container, no repeated work or readiness,
public cookie continuity, actual stopped engine and released execution/retained
original output-allocation facts. These immutable allocation fields do not prove
current debt after refunds; inspect the owning counters separately. Custody is read only after the backend stops, using a bounded
UID1000 reader of the same backend image; serving keeps its exclusive SQLite
lease. The reader permits SQLite sidecars but checks the main-file hash unchanged.
Public resource summaries must be actual Docker-stats provenance
with sampled values and hard-ceiling bounds. This is not a sampling accuracy or
telemetry overhead claim. Logs/failure diagnostics remain private; closed outcome
contains synthetic IDs/scalars only. Always cleanup exact owned installation and
project. No full lifecycle-phase, native other-architecture or soak acceptance.

Readiness HTTP uses one bounded process in the healthy backend peer; repeated
probes never inject Node processes into the recovering quarter-core agent.
Credential stays in-process; only validated capability identity/status is used.

Default crashes and explicit cancel use separate fresh projects. Stock128MiB
agent output pool holds two retained64MiB disk reservations; a third must wait. Never raise
that limit or erase retained results merely to fit cancellation into one fixture.

CI persists installation-owner.json before any offer. Independent cleanup.ts uses
only bounded exact project/installation ownership; see ../README.md for deadlines.
public.ts emits only the closed outcome projection and safe diagnostic locations.
Failed cases retain one bounded last recovery observation, never raw capabilities.

Source-image CI uses the same execution.ts assertions through source-active.ts;
Git head, expected revision and all six native image labels must agree. This is
source-built execution, not anonymous pull proof. Independent cleanup uses always(),
including cancellation; its success cannot promote a failed/cancelled native job.

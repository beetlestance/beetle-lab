# Read-only source conformance qualification

Select missing AMD64 engine/request/admission cases or the30-minute stream.
Reuse the verified required-gate source archive; never rebuild or publish images.
Each profile has its own owned installation and independent cleanup. Normal CI
and the existing short-control profile retain their defaults.

cases.ts/plan.ts declare finite commands; public.ts emits only closed facts from
private reports. outcome.ts and the short/long projectors reject wrong source,
architecture, phase, outcomes or incomplete evidence. No API bodies, config,
exception text, tokens or raw logs enter uploaded artifacts. Failed private
reports remain on the ephemeral runner, with fixed failed case markers uploaded.

The long profile preserves30-minute active and29-minute fresh-reader spans,
three readers, all eight artifact digests, physical work and post-idle samples.
It is not an uninterrupted-availability or process-RSS assertion. The workflows
require execution and independent cleanup success plus a clean matching harness.

Failure projection retains a fixed allowlisted phase and cleanup facts after
source/architecture binding. Unknown phase/error/config fields never pass through.
`long-amd64` selects only the long job, avoiding repeated finite conformance checks.

`conformance-amd64` selects only finite conformance without repeating the stream.
Engine failures retain only fixed error category/source coordinates/HTTP status.

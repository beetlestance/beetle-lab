# Image source material

`catalog.json` is reviewed public pin data; `catalog.ts` captures it and verifies
complete recipe Git trees, modes, names, checksums and k6 provenance bindings.
`inputs.ts` uses staged inventories and exact candidate Git source; `coverage.ts`
checks all OS origins/runtime versions, while `npm.ts` reads production SRI pins.
`assets.ts` and `fetch.ts` collect bounded files without executing downloaded code.
`reports.ts` copies no-follow regular reports under active byte ceilings.
`collect.ts` composes collection; `bundle.ts` publishes only the private complete
marker after deterministic `pack.py` succeeds and the gzip hash is checked.

No registry authority or image rebuild. Existing private verified asset evidence
can be reused for a packing-only change when every manifest input is identical.
README.md describes budgets, prerequisites and pin maintenance. Keep the tooling
separate from application installation and runtime behavior.
